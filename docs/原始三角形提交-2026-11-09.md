# 0.11.0 原版三角形分支接入目标绘图

日期：2026-11-09（Asia/Shanghai）

本轮推进完整交付路线 P3：把 `TGlPrimitive::Draw()` 的 `sgloTriangles` 顶点、法线和颜色分支抽出为桌面与目标端共用的逻辑。不是另造一个相似三角形循环，也不是把完整目标缩小成诊断应用。完整原界面、完整绘图状态、Python/插件及发行验收仍未完成。

## 真实来源与桌面兼容

- `upstream/glib/trianglesubmit.h` 来自固定上游 `glprimitive.cpp` 中 `PrepareColorRendering(GL_TRIANGLES)` 和 `EndColorRendering()` 之间的原分支。
- 只把输出调用改为接收器接口、选取状态查询改为同位置的接收器查询。还原这些名字后，函数体必须与固定提交逐字相同；由 `check-source.py` 检查，不只是肉眼认为算法相近。
- 桌面 `TGlPrimitive` 改为调用共享分支，接收器仍调用原来的 `SetNormal`、`DrawVertex`、`DrawVertex3/3c`，保留真正的桌面 GL。外层材质、begin/end、变换、裁剪、纹理和列表处理未被空实现替代。
- 主机编译完整 `glprimitive.cpp` 翻译单元，防止新包装破坏原接口；此项只是编译，不是桌面 GL 运行或整个应用链接通过。
- 第七份最小来源补丁为 `patches/0007-extract-original-primitive-triangle-submission.patch`。固定提交、许可证、七份补丁、正反重放和精确字节均继续检查。

## 目标边界和状态

`native/primitive_triangles.*` 使用原来的 `TArrayList<vec3f>` / `TArrayList<uint32_t>` 输入。它显式接收当前法线、当前颜色、ForcePlain 与 Selecting，返回实际提交流、最终状态和指令计数。

- 无法线时沿用传入的当前法线，不能偷偷生成面法线。
- 法线可按顶点或每三个顶点一组提交；后一种保持一次 SetNormal 后跟三个顶点的原顺序。
- 原有逐顶点颜色、ForcePlain 抑制颜色效果、Selecting 分支忽略颜色的行为具有 CPU 指令证据。状态可明确传入下一批，不依赖隐藏的 GL 全局状态。
- 共享的原始分支仍保留原来错误属性数量时“不输出”的行为；目标输入边界则明确拒绝错误数量、不完整三角形、超预算顶点、非有限坐标和未定义方向的法线，不能用空画面冒充成功。
- 原生 GPU 材质消费者还没有逐顶点颜色跟踪。捕获流保留颜色指令，但尝试把有效颜色指令送入当前不带颜色的上传接口会明确失败；不会静默丢掉颜色。

## 如何进入实际屏幕

现有真实共享球面/圆环/圆盘/边缘几何输出，先经过上述原版三角形分支，再由其输出进入 GLES 顶点缓冲。原位置、法线、顺序和索引不变；没有保留一个绕过共享分支的平行上传循环。

运行状态另行报告原版分支来源、输出顶点数、法线与颜色指令数、核对结果。应用的几何/颜色/材质/高光、线框、尺寸变化与恢复检查同时要求这条实际上传链成立。高光独立 CPU 像素参照继续使用最终实际提交流，而不是另一份脱离 GPU 输入的网格。

当前实际 GPU 路径使用**不带逐顶点颜色、每顶点法线**的完整三角形流。每面法线、沿用状态、逐顶点颜色、ForcePlain 和 Selecting 的额外分支仍是 CPU/目标原生指令证据，不扩大解释成这些状态都已经逐项 GPU 验收，更不是完整选取引擎。
