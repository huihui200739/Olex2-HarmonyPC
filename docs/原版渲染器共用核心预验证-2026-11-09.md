## 实际接通的链路

- 原 `ApplicationRuntime/TXApp` 空启动、原运行目录、设置及日志对象，由现有工作台持有。
- 图形桥不再创建另一个原运行时，而是借用现有实例，核对原单例和目录，并通过原解释器保护范围串行执行。
- 原 `AGlScene/TGlRenderer`、collection/object/primitive、原 GLU 及 GL4ES，最终提交到当前 XComponent 对应的真实窗口 surface。
- 临时 ES3 context 不与主 context 共享对象；canonical C `gl*`/`glu*` 符号不从共享核心导出，避免接管主 GLES 路径。
- 原图形对象、列表和 GLU 资源在其 context 仍有效时销毁；然后解除绑定、销毁临时 context，最后重新绑定主 context 并恢复 viewport。
- 检查必须包含真正的下一帧主视图、原矩阵与实际 uniform、像素、状态和外部 EGL 绑定。不能用之前独立包的 4×4 父 FBO 代替主视图后续帧。

共享核心实际交叉编译 512 个单元：GL4ES 69、GLU 89、原 glib 27、xlib 272、SDL 47、repository 3，以及桥接/平台 5。父 NAPI/GLES 库另外编译 17 个单元，不再重复编译原核心、运行时、日志、解释器、桌面命令或 glmaterial/gloption。

最初实验导出了 20837 个 C++ 符号。随后依据实际父库的动态引用和共同弱符号/RTTI，改为明确列出的 365 个导出，不再使用 `_Z*` 通配。它只面向当前候选工作台的 ABI，不是完整应用/插件 ABI 认证。

## 保留的失败与修正

1. **切回主画面后 uniform 失效。** `shared-window-20261109-122718-de80a4` 的主 GPU 状态在恢复 context 时仍正确，但销毁另一个 context 后出现错误读值，GL 错误码仍为 0，下一帧矩阵验收失败。调整为“解除绑定 → 销毁临时 context → 重新绑定主 context”后，真实下一帧通过。这里只陈述当前模拟器上的观察和修正效果，不将其扩大为系统驱动根因结论。
2. **旧运行文件混入收集列表。** `shared-window-20261109-123239-938692` 的连续三次绘图各 121 项检查通过，但旧全局文件匹配还收进了一份上轮已不再生成的文件，不能作为最终独占来源证据。改为每个 PID/run 独占目录，并校验目录身份及每份目标/本地 SHA。
3. **独占目录无法收集。** 首版使用 0700，HDC 无法枚举，`shared-ui-regression-20261109-123741-3e62fe` 因收集失败中止。后续仅合成调试产物目录使用 0755，不修改用户数据目录权限。旧失败保留。
4. **比较基线时设置仍在延迟保存。** `shared-ui-regression-20261109-123921-463c1b` 中，视图命令重启后的 `workspaceState.saveStatus` 从 pending 变为 saved，严格连续性验收因此失败。修正为先等已有保存完成再捕获基线；仍逐项要求整个 workspaceState 和其他宿主记录不变，没有排除该字段或放宽相等比较。
5. **新增入口挤压底部控件。** 宽接口候选虽通过既有运行检查，但额外布局检查发现实际 `bounds` 已被裁剪，而 `origBounds` 仍越出面板，原先仅比较裁剪后边界的检查不足以发现问题。按钮移入原视口标题行，取消额外两行和原始 JSON 文本。新增检查要求重置按钮、缩放滑杆与原绘图按钮的 `bounds == origBounds`，并完整位于面板内。
6. **诊断不读取未初始化值。** 原 `TGlLight` 构造没有初始化 short 类型的 SpotExponent。旧失败及读值证据保留。新桥先通过原 setter 为本合成场景明确设置 exponent/direction，再记录配置；未声称修复上游构造函数，也不读取未初始化参数来生成诊断。

`shared-window-20261109-122515-bfb43d` 等仅构建或被后续测量修正替代的产物同样保留，不当作运行通过。

仅测试合成三角形、发光材质 GLU 球和环形圆盘，不覆盖原版全部材质/透明/光照、纹理、字体、选取或完整绘图状态。不是长期稳定性、OOM、设备丢失恢复或所有异常路径验收。原界面/完整业务、Python、插件、完整资源和外部工具尚未接通。
