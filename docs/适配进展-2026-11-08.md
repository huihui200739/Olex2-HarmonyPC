## 四、已修复的 Unicode 正确性问题

对正常 ASCII、双字节字符、中文和四字节 Unicode 文本做转换检查时，发现上游
`TUtf8::EncodeStream4` 中连续字节前缀在掩码运算后丢失，导致正常非 ASCII 字符无法原样往返。
针对目标端使用的 4 字节 `wchar_t` 分支，调整了正常 2/3/4 字节 Unicode 编码中的 6 处表达式。

- 修改文件：`upstream/sdl/eutf8.h`。
- 最小补丁：`patches/0001-fix-utf8-encode4-continuation-bytes.patch`。
- 修改前正常中文往返检查未通过；修改后本轮四种正常文本检查均通过。
- 此补丁未声称完成整个编码模块、其他平台或其他分支的完整验证。
- 中文路径测试使用进程号和独占创建模式，只创建并清理自己的测试文件，不覆盖既有文件。

本轮保留 `patches/0002-extract-shared-sphere-triangle-submission.patch`，并新增 `patches/0003-extract-legacy-helper-primitives.patch`：共享球面提交及圆环/圆盘/边缘循环；`esphere.h` 保持原字节不变。桌面 API 仅编译检查通过，完整渲染器没有运行通过结论，详见原生应用记录。

## 五、界面和图形层的移植难点

上游 `CMakeLists.txt`、`3rdparty/CMakeLists.txt`、`glib/glbase.h` 显示其桌面构建依赖
wxWidgets、OpenGL/GLU、Python、OpenSSL 等。现有基础层构建没有解决这些 GUI 与运行时依赖。

本机 SDK 的 `GL/gl.h` 虽然声明了旧版接口，但 ARM64 `libGLv4.so` 没有导出本轮检查的：

- `glMatrixMode`、`glLoadIdentity`
- `glNewList`、`glEndList`
- `glBegin`、`glEnd`、`glVertex3d`

正向对照检查可链接 `glGetString`、`glClear`、`glCreateShader`、`glGenBuffers`、`eglGetError`，排除了简单的库路径遗漏。
另外，当前检查位置缺少 `GL/glu.h` 和 GLU 库。

这些是本机 SDK 的可复现链接检查结果，不是所有设备和所有版本的普遍结论。
也不意味着鸿蒙不支持 OpenGL，而是原有固定功能渲染代码不能直接链接当前 SDK。

本节 SDK 链接检查只读取库导出和获取函数地址，不执行绘图，不创建图形上下文。后续模拟器诊断尝试建立离屏上下文但初始化失败，详见补充记录；后续已在原生应用窗口验证合成几何体、视角更新、窗口最大化/恢复与生命周期，见原生应用记录；仍未验证原版渲染器、字体、多屏、选取、物理鼠标键盘或帧率。
