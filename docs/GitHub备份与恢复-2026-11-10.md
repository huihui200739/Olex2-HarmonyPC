# GitHub备份与恢复

## 仓库与目的

本轮用户明确要求备份到自己的GitHub账号。目标为私有仓库：

https://github.com/huihui200739/Olex2-HarmonyPC

只有仓库授权者可见；本轮没有将其公开，没有向其他项目推送。备份不等于适配完成。当前交付边界见[具体进度说明](进度汇报与交付边界-2026-11-10.md)。

## Git主分支保存什么

- 根目录原标准基线的app/native/cmake/scripts/patches/docs/experiments及来源锁、许可证、vendor和upstream工作树文件。
- **最新完整集成源码：`snapshots/source28/`。** 对应原 `out/gx-application-evaluation/source28`，2539份文件逐份原字节/原权限复制，清单 `snapshots/source28.manifest.json`。根目录标准app/native不是这一最新版。
- `backup/upstream-history.bundle`保留嵌套上游仓库的Git历史；不提交原`.git`目录或误建只含引用的gitlink。
- `backup/evidence/`保存当前状态、599项字体窗口结果和独立重读、本机结果、最终一致性结果等原字节副本；`backup/evidence.manifest.json`记录原路径与摘要。
- `backup/*20261110.manifest.json`记录两个大归档的完整文件集合、大小与SHA-256；`backup/release-assets.json`记录Release附件与校验信息。

## Release另存什么

备份标签：`backup-20261110-source28`。该Release是**开发备份、非正式产品发布**，标记为prerelease，不代表可供日常使用的完整应用。

- 最新原始未签名HAP；SHA-256：`3c66b1aeda753d2963cfe0e1810d8b3067ec04a7634e0e8bea7e54d8b6c25cb0`。
- `reports-20261110.tar.gz`（如分块则以`.part-000`等结尾）：本轮归档时整个reports文件树，含历史成功/失败报告、原始像素、日志、界面图片和其中保留的产物；不把旧版本报告冒充28通过资格。
- `current-state-20261110.tar.gz`：原位置的source16～28、28最新构建/来源证据、本轮显示参数相关产物与工具、旧副本授权清理与备份审计等。缓存组件`.git`/`__pycache__`/`.hvigor`/`node_modules`/`oh_modules`不打包，完整选择以清单为准。
- `SHA256SUMS`用于附件的逐字节完整性校验。

## 明确没有上传的内容

**不是整台电脑镜像，也不是所有out历史中间文件的全量备份。** 未选择的历史构建目录/临时对象/旧工具输出仍只在本机保留，不能称它们已上传。未上传系统与DevEco SDK、模拟器系统盘/完整应用数据、登录凭据、其他项目和父目录文件。本轮没有因备份再删除任何本机或模拟器文件。

上传前做了内容级凭据检查；它是泄漏预防检查，不是“绝无秘密”的安全认证。

## 恢复源码与记录

以下步骤适用于新电脑或全新的克隆副本；不要覆盖当前仍在工作的本地目录。

```sh
gh repo clone huihui200739/Olex2-HarmonyPC
cd Olex2-HarmonyPC
python3 scripts/restore-github-backup.py
# 恢复缺失的原source28路径；已有目录时会拒绝覆盖。
python3 scripts/restore-github-backup.py --restore-source28
# 根目录原基线校验需要嵌套upstream Git历史，已有.git时拒绝替换。
python3 scripts/restore-github-backup.py --restore-upstream-git
```

第一次命令只验证2539份源码的集合/大小/字节摘要，不进行设备操作。复制恢复时按清单还原权限。不能据恢复成功推定SDK已安装、包可发行或全功能已完成。

恢复完整证据时，在新克隆目录内：

```sh
mkdir -p downloaded-backup
gh release download backup-20261110-source28 --repo huihui200739/Olex2-HarmonyPC --dir downloaded-backup
(cd downloaded-backup && shasum -a 256 -c SHA256SUMS)
# 如果reports为分块，先按名称顺序重组；未分块时跳过这一步。
cat downloaded-backup/reports-20261110.tar.gz.part-* > downloaded-backup/reports-20261110.tar.gz
# 先确认当前目录下没有需要保护的reports/out，再解包；归档保留原相对路径。
tar -xzf downloaded-backup/reports-20261110.tar.gz
tar -xzf downloaded-backup/current-state-20261110.tar.gz
```

`cat`步骤只适用于附件确实分块的情况；先校验分块附件，再重组，完整归档的摘要另见`backup/release-assets.json`。解包会恢复原相对路径，**不要在有新工作成果的目录直接覆盖解包**。如只查看进度，无需下载大附件，直接阅读Git仓库中的进度说明与有限证据。
