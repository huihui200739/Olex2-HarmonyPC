# 原始线段提交与实际线框索引

日期：2026-11-09（Asia/Shanghai）。本篇记录 0.17.0 的 P3 增量，不是完整渲染器或完整应用的完成声明。本轮整轮证据见文末；它只限定于已实现子集，不是完整软件验收。

## 原始代码与桌面兼容

补丁 `patches/0013-extract-original-line-submission.patch` 把原 `TGlPrimitive::Draw(sgloLines)` 的宽度/颜色/顶点提交体抽到 `upstream/glib/linesubmit.h`。入口的真实 GL begin/end、材质、变换、裁剪、显示列表仍在原调用方，不用空 GL 实现消除链接问题。

`check-source.py` 从固定提交读取原体，只反向替换输出 API 名字，要求共享体逐字一致。13 补丁必须正向/反向精确重放；原 `sgloLineStrip` 和 `sgloLineLoop` 分支保持逐字不变，不将它们冒充已接入目标。

桌面包装继续查询/修改真实线宽，转发真实 SetColor/DrawVertex/DrawVertex2。完整 `glprimitive.cpp` 的主机编译只证明接口兼容，不证明桌面运行，更不证明整个类已交叉编译到 OHOS。

## 显式有限目标边界

`native/primitive_lines.*` 捕获无色、逐顶点和逐线段颜色，保留 ForcePlain、Selecting 短路和缩放/恢复线宽的原始分支语义。结果显式携带初始/最终颜色与宽度、颜色请求和命令数量、宽度查询和顺序。它没有隐式 GL 全局状态，也不生成法线。

严格适配入口仅接受成对、有限、总数不超过 200000 的顶点；拒绝非法颜色数量、非有限坐标及不能表示为正有限 float 的线宽乘积。原共享头仍保留原有非法属性数量时不提交、奇数原始顶点提交等行为；这些是旧语义与新严格边界的区分，不是修改原算法或降低测试。

## 实际应用路径

现有四类几何的原边界索引先展开为带独立输入身份的线段位置，经过共享原 `sgloLines` 输出，再按其输出顺序生成实际 EBO。输入身份不是按坐标去重，因此重合位置不会把不同源顶点错误合并。

实际上传只允许无颜色、线宽乘数 1 的路径，颜色/线宽命令数量必须为 0。原三角提交输出仍提供既有位置/逐顶点法线属性；这保留现有自定义材质着色，但**不声称等价于原固定功能 sgloLines 的传入法线状态**。

新路径不新建三角形对角线或圆盘扇形辐条，不改变原圆环/圆盘/边缘批次、尾项或源边界。实际索引缓冲区上传后用 GLES3 只读映射取回字节，逐字节与本次原分支输出比较；摘要来自读回缓冲区，不是重新哈希 CPU 暂存数组。必须成功解除映射并无 GL 错误后才保留当前缓冲区证明。

`originalLineVerified` 是本次原分支验证，`originalLineBufferVerified` 是本次实际 EBO 字节验证，两者与真实绘图像素/覆盖率分别保留。实体上传清空线段证明和摘要，表面释放也清空当前证明；系统文档页的无表面状态不计入 GPU 通过。

## 独立核对与边界

`scripts/line_validation.py` 不调用原生适配器，以独立整数拓扑构造四类图元 0～5 精细度的边索引字节，按明确 little-endian uint32 格式核对 SHA-256。包含球三角边、圆环原四边形条边、圆盘原周边和边缘完整四边形边；保留各源批次的不同原始顶点身份，不按重合坐标合并。

24 类 CPU 源流在主机和 OHOS 独立执行并核对；应用当前实际绘图的每份活跃状态还要以对应拓扑核对实际 EBO 摘要。24 类 CPU 契约不扩大成全部 24 类 GPU 验收；实际 GPU 范围以完整保留应用记录为准。整轮继续保留此前原应用设置、系统文档、原解释器、矩阵/多边形、材质、像素和生命周期检查。

未实现的内容：GPU 逐顶点颜色、任意宽线、原 Picking 引擎、原全部法线/光照状态、线带/闭合线分支、完整图元类、完整原渲染器/UI/Python/插件。真机、物理输入、发行签名独立未验证，功能完成百分比仍为 `null`。

## 开发中发现并保留的问题

- 首次包构建未给 ArkTS 初始图形状态增加全部新字段，编译正确失败，修复初始值而不是降低类型检查。失败 `reports/app/original-lines-verified-app-build.log` 与修复后 `original-lines-verified-app-build-corrected.log` 均保留。
- 独立 Python 契约的首次回归发现默认缓存把整型细分与浮点/布尔等值键混同，导致严格类型检查可能被缓存命中绕过。改为按类型区分缓存后，18 个隔离合成用例通过。失败与修复日志分别为 `original-lines-development-validator-tests.log` 和 `original-lines-development-validator-tests-corrected.log`；不能移除类型拒绝测试来迎合缓存。

- 复查额外补上待提交 VAO/VBO/EBO 的作用域清理；摘要字符串分配等异常会先解除映射，再清理新建资源，不破坏已经由渲染器持有的旧资源。本轮实际窗口重新跑完整检查；没有注入内存不足或 GPU 设备丢失，不能把正常路径通过扩大成对应故障注入验证。

- 最终包首次重跑在执行前读回时发现 `>>` 被当前输入法转换为 `》》`，准确拒绝执行并整轮失败；`reports/app/20261109-055146-58b7d1/result.json` 和其全部布局/输入日志保留。不修改解析器接受全角符号，也不把失败样本重写为成功。针对性UI探测确认 `uinput -K -t` 能注入准确原文；只作为文本注入的最后备选，仍逐字读回真实UI字段，再经原执行控件派发，不直调原生命令，也不改系统输入法设置。临时Shift的恢复事件仍在finally发送，但不扩大成全局模式状态已验证。

- 另一次重跑遇到系统选择器仅有取消/打开按钮、文件列表和搜索框尚未加载的瞬间，准确失败于控件不存在；`reports/app/20261109-060229-dfdbc3/result.json` 保留。后续等候实际文件/搜索框就绪，并逐字读回搜索名，再等候准确导出URI出现，不改所选路径、不绕过系统选择器、不将固定延时当作已就绪证据。
