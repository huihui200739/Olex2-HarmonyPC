# 原应用运行时、目录与设置接入

## 本轮连接的是真正的原应用基础层

`native/application_runtime.*` 创建真实 `TBasicApp`，使用原 `TBasicApp::ExportLibrary("app")` 的22个原函数注册对象。函数表达式由未修改的 `TEMacroLib` / `TLibrary` / `AFunction` 解析和派发，不使用另写的 `app.*` 字符串解析器。

这连接的是原应用基础运行时，不是 `TXApp`、`TGXApp`、`Olex2App` 或 wx 主窗口；完整领域逻辑、原命令库、Python和插件仍未接通。注册22个原函数也不代表22个函数的全部参数和行为都通过运行验收；本轮界面覆盖10个原函数名称。

## 鸿蒙私有目录与资源边界

Ability使用真实 `context.filesDir` 初始化原生运行时，包内许可证通过当前SDK声明的 `resourceManager.getRawFileContentSync` 读取，再以Uint8Array传给原生层。四个目录在应用自己的 `filesDir/olex2-runtime-v1/` 下分开创建：

| 原应用目录 | 当前映射 |
|---|---|
| BaseDir | `base/`，存放准确原许可证副本 |
| SharedDir | `shared/` |
| InstanceDir | `instance/` |
| ConfigDir | `config/`，原格式 `.options` |

`app.BaseDir()` / `app.SharedDir()` / `app.InstanceDir()` / `app.ConfigDir()` 确实由原函数返回这些目录；平台名通过窄范围派生类覆写为目标端OHOS64，主机测试明确返回HOST-COMPATIBILITY-TEST，不把主机结果当OHOS运行。

原许可证必须符合固定来源的SHA-256，写入使用独占临时文件和原子替换。这里的BaseDir是可写私有资源副本，并非HAP内只读资源路径。**目前只映射原许可证，不是完整原资源树打包。** 没有下载空资源、复制主机二进制或用空文件宣称资源适配完成。

## 原设置格式与实际UI行为

原 `TSettingsFile` 读写 `.options`，保留已有注释和未被本次修改的键。没有直接调用会附带修改PATH的桌面 `TBasicApp::ReadOptions`；也没有使用 `OLEX2_DIR`、当前工作目录或桌面启动脚本来猜鸿蒙私有目录。

界面输入以下原函数后点击“应用函数”，会实际改变可见提示，而不只是返回测试标志：

```text
app.SetOption(ui.commandHints,false)
app.OptValue(ui.commandHints)
app.SetOption(ui.commandHints,true)
app.SaveOptions()
```

`ui.commandHints`是新平台UI消费的选项；其他键被保存不等于完整原应用的相关业务已经生效。图形视图偏好仍沿用独立schema4文件，没有另写一套相互覆盖的图元/材质状态。

## 保存钩子与明确的失败语义

补丁0010仅把 `bapp.h` 的 `SaveOptions()` 声明改为virtual；`bapp.cpp` 原实现逐字保持不变。原 `BAPP_SetOpt` / `BAPP_SaveOptions` 因而调用平台派生类的真实保存钩子，不是重新注册同名假函数。

钩子验证有限文本格式，写入独占临时文件，使用原解析器重读并逐键核对，刷新临时文件后rename替换目标。已知提交前错误恢复此前保存的内存选项；不会将失败写成成功，也不会删除已有无关文件。键名限128字节、有限ASCII名称字符，值限2048个UTF-8字节且无换行/NUL，保存时最多256个选项；不声称兼容所有历史选项格式。

- `optionsChanged`表示原选项集合是否变化，不只是可见布尔值是否变化。首次保存默认true也可能新增一个实际键。
- `lastSaveCommitted`表示上一次保存事件；只读函数不等于又写了一次文件。
- `saveRevision`只在本进程成功提交时增加，同内容的显式保存也算提交；新进程从0开始。
- 没有父目录fsync/断电耐久性保证，也不声称任意嵌套原函数副作用具备全局事务回滚。
- virtual声明改变了该类的ABI，当前库须全量重编；没有宣称已兼容未重编的第三方插件。

## 原解释器全局指针的共享保护

视图命令与应用函数共用 `native/original_interpreter.*` 中的原解释器适配和作用域锁。它保留原引号感知连续命令处理，禁止凭新平台字符串分派替代原解析器；结束时恢复旧的当前处理器指针。64次混合调用检查覆盖这两个本地消费者，**不代表所有原库调用方或全局状态均线程安全**。尚未实现的回调明确报错。

运行时由Ability创建并在销毁时释放；表面重建不会重新创建TBasicApp。关闭重启后读取实际 `.options`，但不保存/重放函数表达式、执行序号或历史。

## 发布构建计数修正与保留的失败

界面冷启动复测观察到原函数数量从22变成123。检查原 `ehashed.h` 后发现，非_DEBUG初始化分支只初始化了basket_n，没有初始化count；Clear也没有重置计数。补丁0011只补齐发布初始化和Clear后的计数重置，没有改哈希/比较/插入算法。原始失败保留：

- `reports/app/20261109-042431-0d531d/result.json`：首次新增默认选项的实际optionsChanged=true，原测试期望误将其等同于可见布尔值变化；已修正独立期望并补回归，不修改运行证据。
- `reports/app/20261109-042558-6cc653/result.json`：真实冷启动报告originalFunctionCount=123，原22计数验收没有被放宽。

普通新建、插入、Clear、复用的数量，以及重新创建实际TBasicApp后的22函数数量须检查；不是把输出固定写成22。来源工具严格要求0010/0011的变更与固定提交比对、整条补丁链精确重放并逆序还原。
