# 0.13.0 原始多边形提交与有限平面三角化

日期：2026-11-09（Asia/Shanghai）

本轮沿完整路线 P3 继续接入原始绘图分支，不新增与原应用无关的功能范围。完整原应用、界面、渲染器、Python/插件和发行验收仍未完成；正式结论以文末对应的保留证据为准。

## 原始分支的来源

固定上游提交仍为 `ca2b4c1b68ac9d7d8fddc53eb5fcf60797d2d3e1`。第九份补丁 `patches/0009-extract-original-polygon-submission.patch` 将 `TGlPrimitive::Draw(sgloPolygon)` 内原法线、颜色、顶点提交体抽取为 `upstream/glib/polygonsubmit.h` 共享模板。替换后还原 API 名称，必须与固定提交的原分支逐字相同；来源检查还需通过九份补丁的正向精确重放与逆向回退。

桌面包装继续执行真实的 `glBegin/glEnd` 和关闭面剔除的原守卫，不引入空 GL。整个桌面 `glprimitive.cpp` 只做主机编译兼容检查；OHOS 并没有因此构建整个原始类。

`native/primitive_polygons.*` 捕获继承法线/颜色，保持 ForcePlain 和 Selecting 分支语义。逐顶点颜色与选取的证据仍是 CPU 指令轨迹，不能写成已完成 GPU 颜色跟踪或选取系统。

## 新三角化器的边界

这是新的有限适配器，**不是 GLU，也不宣称与旧 GL 的任意凹多边形行为等价**。

- 只接受一个简单平面轮廓，输入 3～2048 个顶点，可有一个重复闭合点。
- 先归一化坐标，再检查平面性、重复/过短边、自交和非相邻接触；不静默修补无效输入。
- 严格凸轮廓保留原扇形顶点和对角线顺序；凹轮廓使用耳切，允许满足检查的共线边界。
- 保留输入绕序与原索引，边界线框不增加三角化对角线。
- 工作预算上限为 1200 万步。孔洞、多轮廓、非共面、退化、次精度和超预算输入明确拒绝。
- 不生成新的替代光照法线；当前圆盘辅助路径要求一个明确的恒定源法线。

CPU 检查包括 1980 组原始分支状态及 48 组独立拓扑姿态：四个平面、三种尺度、两种绕序、有/无重复闭合。参照使用独立射线穿越、面积、绕序、覆盖和重叠检查，不仅检查三角形数量。

## 实际应用接入

原有六个圆盘面现在先经过共享 `sgloPolygon` 分支，再经显式凸轮廓三角化，之后进入已有的共享 `sgloTriangles` 分支及实际 GLES3 上传。仍保留原六面、原扇形顺序、闭合退化元数据和线框边界；不把圆盘辅助函数扩大为任意凹轮廓消费者。

运行报告必须包含六批多边形、`6 × (8 × (generation + 1) + 1)` 个源顶点、六条法线指令和零条颜色指令。球面、圆环、边缘不得错误宣称使用该原多边形分支。

另有一个**明确标记的通用合成 U 形轮廓**，仅用于 GPU 验证：原多边形分支 → 新三角化器 → 原三角形分支 → 应用实际着色器，在同一应用上下文的 64×64 RGBA8 FBO 中绘制。八个源顶点生成六个三角形，使用合成纯色 `(0.25,0.75,0.5)`。

六个实际读回像素包括三个形状内部点和三个背景点，其中凹口必须保持背景。独立 Python 射线穿越重新计算每个采样点内外关系，不信任原生 `expectedInside` 标签或成功标记。这只证明一个 GPU 凹轮廓用例，不代表所有轮廓/视角/材质都已完成 GPU 验收。

测试恢复并重新查询程序/uniform、顶点与缓冲区绑定、纹理、读/写 framebuffer 及缓冲区选择、viewport、清屏颜色、颜色写掩码和七个相关开关；还核对 EGL 上下文、display、读/写 surface 未变。随后主窗口的真实几何、材质、矩阵和标记像素检查仍必须通过。

## 状态恢复问题与保留失败

本轮曾出现“凹多边形读回正确，但主窗口随后变黑”的回归；没有删除窗口像素门禁或把失败报告改成通过。四次 FBO/共享上下文及两次未呈现窗口路线尝试均保留。关键观察保留在 `reports/app/20261109-025459-5ed3ae/`：同一颜色写掩码，布尔查询为全零，而整数查询为全一。

最终状态查询改用整数形式读取布尔状态，并将原生查询输出放入独立临时数组，只复制该状态要求的分量，不让查询接收区直接邻接已保存状态与句柄。额外的 API 分阶段检查记录真实 GL 错误，任何错误都令验证失败；没有吞掉错误来通过测试。相关失败与诊断运行（包括 `20261109-025634-fefe45`、`20261109-025828-58f7a0`、`20261109-030011-c729c8`）仍保留。

目前不对模拟器内部实现作更深的原因归属；修正是否成立，依赖最终包的 FBO 像素、完整状态恢复以及后续主窗口/交互/生命周期回归共同证明。
